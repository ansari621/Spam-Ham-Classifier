# Spam or Ham Email Classifier (from scratch)

A spam email classifier built **from scratch in pure Python**: tokenizing, TF-IDF features, Multinomial Naive Bayes, stratified train/test split, cross-validation and evaluation metrics are all hand-written, with no machine-learning libraries.

Built for the *Foundations of Machine Learning* course (Assignment 3: SPAM or HAM).

## Results

| Measure | Value |
|---|---|
| Dataset | 2893 emails (481 spam, 2412 ham) |
| Split | 85% training (2459) / 15% test (434), stratified |
| Best settings | TF-IDF features, minimum document frequency 2, alpha = 0.1 |
| 5-fold CV accuracy | 99.51% |
| Held-out test accuracy | 99.77% (precision 1.00, recall 0.986, F1 0.993) |
| Test confusion matrix | TN 362, FP 0, FN 1, TP 71 |

> **Note:** the ham emails in `messages.csv` are mostly linguistics mailing-list posts, so these scores are optimistic for general email. Training on a more varied dataset would make the model more robust.

## How it works

```
messages.csv -> stratified 85/15 split -> tokens -> TF-IDF vectors
             -> Naive Bayes (tuned by 5-fold CV) -> model/model.json -> predict 1 (spam) / 0 (not spam)
```

1. **Preprocessing:** lowercases text, removes email header lines, keeps words, numbers and the symbols `$ ! %`.
2. **Features:** bag of words or TF-IDF (sub-linear TF x IDF, L2-normalised). The vocabulary keeps words found in at least 2 training emails.
3. **Model:** Multinomial Naive Bayes with Laplace smoothing, computed in log space.
4. **Tuning:** 5-fold stratified cross-validation over feature type (bag of words, TF-IDF) and alpha (0.01, 0.1, 0.5, 1.0).
5. **Evaluation:** accuracy, precision, recall, F1 and confusion matrix on the held-out test emails.

## Project structure

```
.
├── messages.csv             # dataset (subject, message, label; 1 = spam, 0 = ham)
├── src/
│   ├── preprocessing.py     # stratified 85/15 split + tokenizer
│   ├── feature_extraction.py# bag of words / TF-IDF
│   ├── naive_bayes.py       # Multinomial Naive Bayes
│   ├── evaluation.py        # accuracy, precision, recall, F1
│   ├── train.py             # tuning (CV), final training, test score
│   └── predict.py           # classify every email*.txt in ./test
├── model/model.json         # trained model (generated by train.py)
├── training_data/           # generated: ham/ and spam/ folders (85%)
├── test/                    # generated: email.txt, email1.txt, ... (15%)
└── test_labels.csv          # generated: true labels of test emails
```

## Requirements

- Python 3.9 or newer
- No third-party packages

## Usage

Run all commands from the project root.

```bash
# 1. Create the stratified split (training_data/, test/, test_labels.csv)
python src/preprocessing.py

# 2. Tune, train, save the model and print test results
python src/train.py

# 3. Classify every email*.txt in ./test  (1 = spam, 0 = not spam)
python src/predict.py
```

`train.py` runs step 1 automatically if `training_data/` is missing.

Example output of `predict.py`:

```
email1.txt: 0
email2.txt: 1
...
```

### Use it from Python

```python
import sys
sys.path.insert(0, "src")
from predict import predict_emails

print(predict_emails())          # [('email1.txt', 0), ('email2.txt', 1), ...]
print(predict_emails("my_mails"))  # use another folder of email*.txt files
```

### Classify your own emails

Put each email in a text file named `email1.txt`, `email2.txt`, ... inside a folder called `test`, then run `python src/predict.py` from the folder that contains `test`.

## Limitations

- Only single words are used (no word pairs, no HTML or header analysis).
- Naive Bayes assumes words are independent, which is not true but works well for spam.
- The dataset is narrow, so performance on very different emails can be lower than reported above.
